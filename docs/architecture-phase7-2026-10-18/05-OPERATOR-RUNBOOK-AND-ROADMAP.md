# Operator boundaries and unfinished integration

## INSPECT: read-only

Use the exact reviewed source and fixed environment identity. Verify current
source/controller/database/image identities independently; Git HEAD does not
identify production. The private journal inspector is described in
`04-OPERATOR-STATUS.md`. It observes history only. On production, restrict any
additional queries to bounded metadata; never export customer records or secrets.

Check actual Docker identities/specifications/networks, effective units/timers,
host/manual processes, connection pools, direct clients, queue/lease/backlog
states, prepared transactions, locks, backup age and independent restore/replica
proof. Unknown actors block. Main is unprotected and rulesets are absent; timer
disablement alone does not prove every deployment hook is inert.

## PREPARE: no production privileged effects

Accept fresh exact-source CI archives and controller source inventory. Preserve
migration001–150 bytes and the unselected coordinated manifest. Do not substitute
an overlay, prior image tag or earlier artifact receipt. Prepare a complete writer
inventory and source-bound plan, independently reviewed image/controller identity,
current-data preservation expectations and reconciliation decisions. Readiness
reports and successful CI cannot issue authority.

## REHEARSE: positively owned synthetic resources only

The guest bootstrap accepts only the fixed dedicated staging host, signed pinned
Ubuntu image, bounded resources, restricted networking and content-addressed
source. Consumed attempts are retained. The narrow unstarted-launch repair is
not a general retry; a real guest execution cannot reuse it. Guest installation
must use its clean exact source and a new private backup each time. Never point
this installer at the primary Node. Current guest is powered off with disks and
receipts retained; there is no automatic restart/adoption path.

The fresh150 wrapper uses its separate PhaseVII project/marker and loopback
230xx ports. Run INSPECT first with exact fresh artifacts; then REHEARSE only
within the authorized dedicated staging environment and after resource checks.
A failure retains this attempt and stops only positively attested owned services.
Do not delete unknown volumes or reset queue state to unblock it.

## EXECUTE: currently BLOCKED

No schema150 production command is admitted by this source. Do not remove the
protective exception, choose an older148 operation as an ordinary final state,
or run a migration shell script against production. The existing protected
controller and independent single-use issuer must remain the sole authority.

The eventual sequence must verify positive provider scope first, capture durable
original roles/services/ingress/object/boot preimages, arm boot restrictions,
fence ingress/supervisors/workers/object writers/roles, drain sessions and reject
prepared/unknown activity, verify original-role-aware backups and independent
restore/replica, execute captured147/148/149/150 with schema checks and READ_ONLY
intermediate states, verify preservation, recover providers privately, accept the
exact candidate, pass the existing protected write handoff, activate compatible
workers and ingress, and clear the boot barrier last. Current source supplies
several of these effects, not their complete privileged coordinator integration.

## Failure response

Before any SQL commit, inspect the actual transaction/database state; only an
uncommitted transaction can be rolled back. After any147+ commit, keep legacy
workers stopped and the system restricted. Never restore broad legacy grants,
claim the old application is compatible, or call backup restoration an ordinary
rollback. Lost COMMIT acknowledgement requires reconnecting to the exact cluster
and checking schema/function/grant/checksum state; it is not permission to retry
SQL or replay consumed approval. A missing/corrupt preimage/journal or unexpected
actor requires independent recovery while maintenance remains armed. Preserve
all evidence. Fresh authorization may be required for forward repair.

Provider NOLOGIN does not disconnect old sessions. A successful systemctl start
exit code does not prove a unit ran: the native guest test returned0 while a
negative condition correctly skipped execution. Verify effective state, jobs,
PIDs and database activity. Private provider startup cannot establish business
write authority. Retain role preimages; never infer generic LOGIN defaults.

## Acceptance and independent approval

Verify exact source/images/controller, schema150 and all three protocol2 values,
Auth/login/refresh/MFA/AAL2, private/public Storage byte ownership, tenant access,
notification/outbox/deletion work, reservation integrity, READ_ONLY restrictions,
worker consumption and graceful recovery, queue/error metrics, and a new backup
with independently functioning restored application. Auth/Storage activity may
write legitimate state: preserve a quiescent pre-resumption database/object
checkpoint and verify original identities/objects after controlled acceptance;
do not silently ignore tables to make preservation pass.

A technically validated candidate still requires independent human review,
administrator protection, current-production backup/restore/replica evidence,
maintenance window/reconciliation approval and fresh protected authorization.
No such approval was issued in this phase.
